# AGENTS.md

## Project

- Python library for fluctuation analysis and long-term-dependent (fBm) time-series generation.
- **PyPI name is `FluctuationAnalysisTools`, import name is `StatTools`** — `pip install StatTools` installs an unrelated package.
- Layout: `StatTools/` (Python package), `src/cpp/` (C++ core compiled via pybind11), `tests/` (pytest suite), `tests_manual/` (manual/scratch scripts, **not** part of the suite), `research/` and `examples/` (Jupyter notebooks).

## Setup

```bash
python -m venv .venv            # on Windows: .venv\Scripts\activate
pip install -e .                # also compiles the C++ extensions; needs a C++ compiler
pip install pytest pytest-timeout filterpy
pre-commit install
```

- `pip install -e .` builds two native modules into `StatTools/native/` (`C_StatTools` — deprecated, slated for removal in 2.0 — and `StatTools_bindings`). The `*.pyd`/`*.so` artifacts are gitignored; without them imports fall back to `None` and binding tests skip.
- `StatTools/_version.py` is generated by setuptools-scm. Never edit or commit it.

## Testing

- Run the suite: `python -m pytest tests/`. Target `tests/` explicitly — a bare `pytest` also collects scratch scripts in `tests_manual/`.
- Single test: `python -m pytest tests/test_dfa.py -k name_of_test -v`
- Tests require `pytest-timeout` (per-test `@pytest.mark.timeout(...)` marks, up to 300 s). Kalman-filter tests need `filterpy` (the `[experimental]` extra).
- Tests that are too slow for CI are guarded with `skipif os.getenv("GITHUB_ACTIONS") == "true"` — they run locally but are skipped in CI, so local runs take longer.
- Many tests generate long synthetic series; statistical tolerances mean occasional flakiness is possible rather than a code bug.

## Style, commits, release

- pre-commit enforces black + isort (black profile) plus trailing-whitespace / end-of-file checks; CI runs it too: `pre-commit run --all-files`.
- Commit messages MUST follow Conventional Commits (`feat:`, `fix(scope):`, `feat!:`, ...). See CONTRIBUTING.md.
- Version comes from setuptools-scm off git tags matching `release/X.Y.Z`. Releasing = push a `release/X.Y.Z` tag: `test-and-release.yml` builds wheels/sdist (Windows/macOS/Linux, Python 3.11), runs tests, creates the GitHub Release, and publishes to PyPI. Update CHANGELOG.md manually.
- PR CI (`run-tests.yml`): pre-commit → build → install from the built wheel/sdist → pytest on 3 OSes, Python 3.11.
- `setup.py` uses an explicit `packages=[...]` list: a newly added subpackage ships in wheels only if added there.

## C++ side

- C++ sources live in `src/cpp/` (`StatTools_core.cpp` shared by both bindings; `StatTools_C_API.cpp` = old C API, `StatTools_bindings.cpp` = pybind11). Changes require a rebuild (`pip install -e .` or `python setup.py build_ext --inplace`) to be visible to tests.
